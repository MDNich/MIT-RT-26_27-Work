\section{Implementation order and open decisions}
Implement identity/discovery and status first; then loss-aware telemetry transport
and archival provenance; then one H.264/SRT channel across Mac/Windows; then the
full video wall, previews, session limits and fault injection. Finally qualify
the actual radios and cameras with all ten machines. Each stage preserves the
existing local device-control boundaries. The proposed protocol is independent
of whether Python bindings, a bundled native helper or another library implements
the transport.

Future hardware commands require a separate revision defining stable request IDs,
expiry, authority, requested/dispatched/confirmed/failed/unknown outcomes and
device acknowledgement. A TCP write or HTTP success is not a hardware outcome.
Non-idempotent actuation SHALL not be retried merely because acknowledgement was
lost. These constraints reserve the boundary; they do not invent the unresolved
board protocol or enable remote actuation in this draft.

\section{Traceability and document maintenance}
SYS/UI/DATA/NET/PKG/ID/DISC/TEL/VID identifiers are stable requirements. T01--T24
are future acceptance cases. Changes to mandatory wire fields, event meaning,
channel mapping or transport behavior require a revision entry and example
updates. Keep design version, wire protocol version and application version
separate. Application support is established by implementation and test evidence,
not by this document's existence.

The accompanying JSON files are protocol examples, not real flight measurements
or cryptographic credentials. A documentation validator checks their syntax,
cross-file identities, observation hash and referenced paths; it does not certify
a server implementation. Rebuild the PDF with \code{make}. Use \code{make clean}
to remove intermediate TeX artifacts while preserving the final PDF.
